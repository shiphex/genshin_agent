# Story评测与评审

## 摘要

[scenarios.json](scenarios.json)维护固定轮次、原题绑定、criteria和禁止断言，按题库SHA-256校验，不自动追随原题变化。原题与场景均未因程序验证获得用户逐题验收。

## 场景矩阵

| Agent ID | 内容 | 原题后缀 |
| --- | --- | --- |
| a01–a05 | 单事实、原因、两主体、预置证据、模糊指代 | 021、004、105、010、无 |
| a06–a08 | 人物延续、知情范围、插入话题后返回 | 001、002、020/021 |
| a09–a11 | 改问对象、前后者、保存证据性质 | 039、105、011/102 |
| a12–a16 | 身份等同、第三降临者、苏醒机制、七王姓名、月矩力成因 | 047、057、066、107、097 |

后缀指 [原题库](../../rag/eval/questions.json)的gq2-ID。每场景评分包含场景标准和引用原题各条criteria，不匹配关键词评分。多轮2–4轮，使用该次实际首轮回答继续，追问固定。a04有标明的预置冻结字段；其他评分材料不进入被测输入。

场景测当前对话内状态，不测跨进程永久记忆。证据边界限于2026-06-05快照及本次来源，不推断最新剧情是否揭晓。等价证据可支持回答，不强制唯一查询或工具顺序。

LiveProvider同时执行V0固定历史检查；摘要、裁剪或其他历史变化仍被拒绝，不能以符合性失败推断剧情语义差。当前剧情评分只适用于该固定历史配置，未测SDK自主上下文策略。符合性、执行、API、引用及语义分别报告，SDK架构选型还须结合适配声明和实际任务表现。字段见[公共协议](../support/protocol.md#运行结果)。

## 重复运行

Agent默认重复3次，每次干净worker／会话。统一Qwen、提示词、生成参数、检索器、语料与预算。索引每次运行只构建一次，建索引和启动单列；轮次从提交用户输入到结果计时，完整场景不含启动和清理。provider耗时另存。真实服务缓存不由框架清除，比较前须保持部署及其他负载一致。

共享资源、usage及追溯约定见[测量说明](../support/measurement.md)。原生工具接口与期限见[公共协议](../support/protocol.md)，命令见[README](README.md)。

## 评审与报告

export生成匿名候选编号、完整轨迹、逐轮回答、实际工具证据、冻结原文、原题标准和禁止断言。只将package.json与review-template.json交pi；binding.json是本地方案／样本映射，不供judge阅读。包内输入与回答均为待审数据，其中指令不能改变评审任务。

SDK身份和适配声明仅在本地manifest与候选报告展示，不导出到匿名评审包。

pi用自己的模型填模板：reviewer及每条verdict=pass／fail／uncertain、rationale、非空evidence_refs。定位支持 `turn:1`、`trace:1`（样本内一基序号）、`source:e1`、`retrieved:片段ID`；无输出时可用 `sample:execution`。模板不含虚构评分。

导入核对包哈希、原运行身份、完整的该样本criteria集合和证据定位。可只提交部分样本，每个提交样本须评全部标准。AI／human分别追加文件，各自使用每样本最近导入，保留历史。全部必需标准pass且执行完成才记该类语义通过；fail、uncertain、未评和执行不完整分别展示，分母含全部计划样本。

AI与人工不一致记争议，观点并列；人工文件不自动代表用户验收。引用检查只核对ID是否在该次已见证据，不判断断言支持。报告按候选／阶段给执行、耗时、资源、V0协议符合性与适配声明，语义另列。计时包含适配器，并列多个run不代表同条件可比。


迁移前历史运行原位只读，可以导出评审包供阅读或生成新报告，但不能导入评分改写旧运行。新分类运行通过manifest的layout_version=2标记；导入仍逐项核对原始冻结材料与运行身份。

全量扩展保留所有支持类型的剧情字段，含角色冒险笔记与已确认权能故事，编年史和图书馆标为`wiki_compilation`，其他资料为`wiki_excerpt`；两种都待语义核验。原七字段增加`source_spans`与`source_kind`；范围是解码原字段字符串的零基半开字符范围。默认目标800字符、无重叠，同流程对白不拆单条；显示语法只作确定性清理。

两个脚本入口继续使用标准库和uv，全量提取实现拆到`scripts/full_corpus.py`辅助模块。评测默认full、显式sample，缺少全量语料就报错；LexicalIndex每轮只构建一次，仍用原词面IDF匹配，不是向量检索。

## 已确认范围与约束

RAG 为主角／派蒙剧情分析 Agent 提供资料和证据。当前是离线最小实验：字段提取 → 词面检索 → 本地模型回答 → 人工检查。Python 必须通过 uv 运行；当前两个脚本仅依赖标准库，无 Python 应用框架。

原始快照在项目共享的 `data/raw/genshin_wiki_data_20260605/`。RAG 专属文件集中在本目录：`scripts/` 为两个脚本，`tests/` 为测试，`experiments/mvp/` 为选择清单、题目、配置和观察记录，`data/mvp/` 为派生语料及全部历史结果。共享 uv 缓存继续位于项目 `.cache/uv/`。

保留剧情字段，排除数值强度、技能倍率、配队、培养和攻略。对白中的力量、战斗和人物能力属于剧情，可以保留。疑似混合机制文本、空字段、错页、模板、重定向、来源不明确和未解析标记进入排除记录。原始快照只读，输出路径防写保护不能因目录调整失效。

## 当前数据与接口

- `experiments/mvp/selection.json` 显式选择 l01–l30，专题是“钟离、契约与璃月历史”，来自 10 个原文件，覆盖角色、书籍、武器、圣遗物和两类任务。
- 每个片段只有 `id、title、type、parent_id、text、source_file、source_pointer` 七个字段。Pointer 是 RFC 6901 字符串列表，可组合原字段或同一流程中的连续对白。`source_file` 相对共享快照根目录，不随模块位置变化。
- 保留完整故事节、书卷正文或已选的连续对白，不生成模型摘要；选项标为“玩家选项；分支关系未知”，空说话者和 `？？？` 不自动补名。
- 检索为中文相邻双字／英文词的 IDF 加权重合，返回 Top 5；不是 BM25 或向量检索，分数不代表语义置信度。
- 12 题为 4 道事实、3 道跨来源、2 道模糊、1 道资料不足、2 道强度。每个期望证据组内是可替代片段，跨来源题必须覆盖所有组。空列表表示样本不能回答，不计为检索成功。
- 题目参考判断状态为 `draft_for_human_review`，回答语义状态为 `pending_human_review`。人工检查目前按题目保存，baseline／RAG 的差异写在备注中。

## 本地模型配置与运行

当前实验使用 llama.cpp 服务 `http://127.0.0.1:8000/v1`，模型 ID 是 `unsloth/Qwen3.5-4B-GGUF:UD-Q6_K_XL`。配置在 `experiments/mvp/local_api.json`；`model=null` 时读取服务唯一模型 ID。温度 0、seed 42、输出上限 1,536 tokens，思考输出关闭。鉴权仅支持环境变量，文档和配置不保存密钥。该模型只被确认用于本次实验，不是最终角色 Agent 的已定模型。

以下命令从项目根目录执行，全部使用共享 uv 缓存和已安装的 Python，不下载依赖或解释器：

```powershell
uv --cache-dir .cache/uv run --offline --no-python-downloads --python 3.11 python rag/scripts/prepare_rag_mvp.py
uv --cache-dir .cache/uv run --offline --no-python-downloads --python 3.11 python rag/scripts/evaluate_rag_mvp.py --dataset sample --retrieval-only
uv --cache-dir .cache/uv run --offline --no-python-downloads --python 3.11 python -m unittest discover -s rag/tests -v
```

真实模型对照命令与可选参数见 [README.md](README.md)。目录迁移验收只运行临时目录中的准备和纯检索，不默认重跑或覆盖已有模型实验。

## 已验证事实

- 原实验有 30 个片段，总文本 11,913 字符，七字段可按原文重建，选择清单的 30 条没有排除项；这不是对全库的语义质量证明。
- 当前小样本的 9 道可答题，Top 5 均找齐标注证据；该结果不能外推为全库检索效果。
- 第二次真实模型对照有 24 次调用，全部 `finish_reason=stop`，失败、截断与不明结束均为 0，调用耗时约 233 秒。这是调用完成事实，不是语义正确率。
- 第一次输出上限为 768 tokens，出现残缺回答，旧版未记录完成原因；保存在 `data/mvp/model_comparison_initial/`，不用于完成率结论。
- 17 项测试覆盖过滤、剧情力量保留、原文定位、对白连续性、词面检索、跨来源证据、提示词、API 错误和完成状态。
- 独立只读审查发现的截断误计成功、HTTP 中途断连丢结果、评测输出可污染 raw 三项问题均已修复并有复现测试。

历史报告见 [完整模型对照](data/mvp/model_comparison/review.md)。此前实跑的具体错误和观察见 [observations.md](experiments/mvp/observations.md)，实现记录见 [implementation_notes.md](experiments/mvp/implementation_notes.md)。

用户指出，无检索回答把达达利亚让旅行者保管神之眼的剧情和钟离的神之心交易混在一起。已有原文支持以下两件不同的事：

## 候选设计，不是固定约束

用户倾向最终 Agent 默认自然角色回答，并提供可展开出处，但明确不希望这么早固定。最终展示方式、角色口吻、模型选择和证据展开交互均待后续设计。`baseline`、`rag`、`ok` 是实验标记，当前没有玩家界面。

用户希望最终 Agent 从对话分析玩家进度；本阶段 RAG 不实现防剧透过滤。当前无 SQLite、Embedding 或图谱仅是 MVP 取舍，后续可按数据规模、独立问题和实测瓶颈调整。

下一轮候选方向是更严格的引用归属、不确定性保持及独立问题评测，尚未承诺具体实现顺序。

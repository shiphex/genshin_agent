# Agent Note: RAG 当前状态基线

Status: implemented

## 问题

旧资料管理按八类目录、版本和运行编号积累历史。用户认为其中多数没有当前用途，要求保留当前RAG、110题、20题核验和三题模型Smoke，并将当前状态设为新基线。

## 决策

首次重整采用schema_version=2的catalog统一登记当前文件与指纹，current-001的data保留corpus、review20、smoke三组10个文件。用户随后明确补充第三方摘要与提示词原件，current-002在原件字节不变的基础上增为11个文件，现行规则见[数据管理](../../../rag/docs/data.md)。原文准备副本和HF staging按需生成，不作为常驻重复资料。新运行写入outputs下独立用途和编号，不改变基线。

迁移保留语料、110题、20题核验原件、模型结果、初审、必要原文和两份实际执行源码的字节。删除旧14题原型、样本、旧模型实验、发布ZIP、Git bundle、整理归档、重复报告和过程证据，不再建立完整备份或旧路径兼容。原始快照不动。

三题输入从旧12题逐行提取；catalog分别记录原输入哈希与选出文件哈希，不把新文件冒充历史执行输入。旧原件中的运行ID保持历史身份。

HF仅导出语料及审计附件，显式配置story/train加载唯一corpus.jsonl；不上传题库、回答或原始快照。构建及校验行数来自当前数据，不再固定旧版本目录。新格式尚未上传。

## 考虑过的替代方案

仅删除重复文件仍保留大量无用版本；按原八类结构删留虽减少空间，仍使当前资料分散。用户进一步选定三个用途目录，并选择只保留Smoke结果与必要依据，淘汰完整过程记录。

## 验证

迁移前101项RAG测试通过；淘汰旧功能并补充基线行为测试后，当前50项通过，项目文档检查器4项测试通过。13个保留文件与11,439个共享原始文件哈希一致；110题445条出处、20题87条来源条目（86处唯一位置）、Smoke的15条证据、7处初审原字段和16处错误摘录均核对原文。

实际准备110题并运行三题纯检索，预期证据组全部覆盖、模型调用0、catalog未改变。隔离uv环境以datasets 5.1.0加载HF的story/train，得到22,822行，全部ID及首尾记录一致，未混入metadata；未上传。文档预算、173个本地链接及Git差异检查通过，未重新语义验收。

独立只读审查发现HF嵌套写入、报告覆盖和默认输入未核对基线指纹三项问题，分别先用失败测试复现，再修正并通过全套回归。默认构建的小型夹具测试另发现已移除sample参数的残留调用，已移除；过滤与切块逻辑不变。开发题skill的新增题／措辞修订两项只读场景定位正确；不宣称客户端自动发现已验证。

## 影响

旧工具、sample参数、旧路径和复杂标注格式退出。Git不保存被忽略的完整原件；新克隆需要另行取得基线数据。删除资料不能由重新运行恢复，本次淘汰范围来自用户明确选择；后续唯一回答和核验仍不能自动清理。题库、第三方初审和模型初审均未升级为用户通过。

审查列出的两项小改进留待后续：原文准备被Ctrl+C中断时可能留running状态，编号仍不复用；新全量构建暂未记录原始目录逐文件内容指纹，仅记录路径／快照名和执行脚本。当前迁移已核对全快照哈希，不将该一次核验冒充未来构建的自动能力。

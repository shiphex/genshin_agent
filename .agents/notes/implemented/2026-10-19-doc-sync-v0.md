# Agent Note: Doc Sync V0

Status: implemented

## 问题

预算门禁已有，但源码参数和文档链接漂移尚无自动拦截。目标是在不改变 RAG 行为、不读取本地数据的前提下补齐开发及 CI 验证。

## 决策

1. 在 refactor/ai-native 的 1ccdbce 基线上实施，仅核对 origin/main 差异，不合并主线，保留分支规范更新。
2. AST 读取 evaluate_retrieval.py 的直接 argparse 定义，在 rag/README.md 唯一受控区生成参数表；未知动态定义失败，不执行源码。遵循标记行换行符，避免 Windows CRLF checkout 误报，保留区外字节。
3. Git 文件清单限定仓库链接和维护中 Markdown；本地 data 路径显式报告豁免，冻结交接材料不作为源扫描，入链仍检查。
4. 项目层 doc_sync.py 顺序调用预算、链接、生成新鲜度检查；Docs Job 复用，保留项目测试与 RAG Job。操作和范围由[开发流程](../../../docs/development.md#文档同步)维护。
5. 扩充现有 doc／pre-push-checks，生成事实与人工语义分开，不新增 Skill。上游实际源码与调用关系见[适配说明](../../skills/doc/references/upstream.md)。

## 考虑过的替代方案

导入或执行 CLI 取得 parser 会耦合业务导入和运行副作用；当前直接定义用 AST 即可。预算清单直接充当链接扫描清单会漏新文档，改由 Git 自动发现。通用调度器、全项目 API 生成均超过单试点需求。

独立 type-equiv 暂缓：现有 LexicalIndex 示例及 catalog 函数无稳定声明型 Schema，动态字典语义靠行为测试；不为检查重构或补造类型。CLI 表已可精确验证参数定义。Agent V0 出现明确公开配置／消息声明后再按源码—文档一对一登记。

## 验证

先观察缺失检查器的失败，再通过隔离仓库中的真实 CLI 生成／校验闭环验证旧默认值表失败、重新生成恢复、生成内容篡改、非法标记、动态定义拒绝及检查只读。链接负例覆盖缺文件、源码移动、坏锚点和未定义引用；本地数据和冻结来源豁免可见。审查后增加 CRLF 与目录根误报的先失败后通过用例。

本地项目级 unittest 15 项、现有 RAG 合成回归 68 项与 doc-sync 通过；无剧情数据、模型或密钥的仅仓库文件 LF 副本通过同一 Docs Job 两条命令，前后文件哈希一致。CRLF、目录根、强调／引用标题及链接 title 误报均有回归。未运行远端 Actions、真实模型或全量评测。两个 Skill 经独立只读默认值变化／内部重构场景及头部结构验证；不代表客户端自动发现已验证。

## 影响

Markdown 标准库检查仅支持约定语法，不冒充完整 CommonMark 渲染器。运行时回退、失败语义、自然语言与未登记接口不能靠生成表证明，仍需源码、行为测试及人工审查。

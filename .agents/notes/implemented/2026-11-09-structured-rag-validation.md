# Agent Note: 结构化RAG的受控探针与执行封存

Status: implemented

## 问题

新语料改变快照、片段ID及模型证据，旧A06探针仍绑定旧位置与环境。直接替换路径会破坏出处约束，也不能把新旧结果差异单独归因证据结构。

## 决策

独立实验分支组合94a46ef与387067c；迁移题库只作实验输入，场景语义和当前基线保持原样。A06重建O/A/C2并定向扩展a07/a10/a11；固定同一批V2模型证据，仅改变content表示，保留说话者、来源、限定与质量提示。规则由[实验说明](../../../probes/structured_rag_validation/README.md)维护。

模型执行要求当前源码和输入与prepare指纹一致，报告后处理允许读取核验后的执行源码封存，单独记录报告源码与变化文件。r001运行于0ec0c09；报告修正tool_calls计数不重写模型原件。评分必须带原阶段hash，拒绝跨run重绑。

## 考虑过的替代方案

- 只重跑新RAG：成本较低，但不足以分离呈现影响。
- 完整旧新全栈重跑：需旧快照环境，且同时包含语料与切块变化。本次选择新RAG复验加同证据对照，旧r003仅历史参照。
- 在原分支继续改探针：会混合旧复现入口；因此保留两个原分支及原产物。

## 验证

68次API正常结束，10次工具调用，六组成对payload仅预定内容变化；输入、执行封存、场景、评估版本及14份基线指纹核验通过。三个独立AI评分任务与两个启动入口试读完成；29项新增离线测试通过。完整结果见本地Benchmarks/outputs/agent_story/structured_rag_validation/r001，当前结论见[模块context](../../../Benchmarks/context.md)。

## 影响

A首答与扩展场景仍有语义失败；C2及呈现对照的第三问能正确归属，不算端到端提升。固定seed的相同重复不支持统计显著性，不推断4B永久能力上限。用户验收、Linux、SDK比较和性能仍未验证；本地基线不自动提升，输出不进入Git。

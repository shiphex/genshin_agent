# 文档开发与审查

按读者任务组织文档，先找信息维护位置再编辑。它编排文档工作，不拥有产品行为定义，也不替代语义判断。长期规则读根 [AGENTS](../../../AGENTS.md)，分类与模板规则读[文档规范](../../../docs/AGENTS.md)。

## 工作步骤

1. 确认任务是创建、修改还是只读审查，明确文件和读者范围。代码涉及对外接口、配置字段、数据格式、默认／失败行为、模块职责或数据流时，按[文档同步流程](../../../docs/development.md#文档同步)分析影响；仅内部重构、局部修复或格式调整且未改变约定时，不强制改 Markdown。读目标页面、规范、导航及相关代码／测试／记录，不遍历全部历史。
2. 判断现有文档能否承载。依据文档规范的 kind 映射打开对应[模板](templates/)，先列出需要更新的事实及其维护位置，不新建相同说明或手写第二份接口／状态清单。
3. 起草或审查。使用[术语约定](../../../docs/terminology.md)，保留必要英文。普通页面区分摘要、页内目录、正文与非权威 Dev Note；文件夹索引只导航。需要精简时使用 [prose-standard](../prose-standard/SKILL.md) 判断含义是否完整。
4. 核对命令、字段、默认值和失败行为。读代码是静态核验，实际执行才是实测；可能生成产物、调用模型或覆盖已有结果时先核对任务授权。找不到证据则报告限制，不补猜，不通过修改重要定义掩盖冲突。
5. 更新权威位置及受影响链接。可机械推导的内容用已登记生成器重新生成，不手改受控区；人工同步语义、限制与架构。CLI 试点和生成命令见[RAG 参考](../../../rag/README.md#检索-cli-参考)。发现实现与已确认行为冲突时先报告证据，不为门禁改业务或把实现错误写成规范。区分本地数据、仓库入口及外链，不改冻结材料；新增现行页面同步预算。
6. 按[验证入口](../../../docs/development.md#验证)运行对应行为测试及 doc-sync，再完整读差异，检查重复、遗漏和模板。doc-sync 不证明自然语言语义、运行时回退或未登记接口一致。小修不要求 Agent Note、全量测试或模型实验。
7. 交付受影响文档、同步结果、事实依据、实际检查、未验证项和剩余问题。只读审查返回发现与建议，不编辑；不能把 AI 初审记为用户验收。

## 验证本 skill

显式读取本文件，给出修链接、同步模块说明或文档冲突的具体任务，观察是否定位权威来源、避免复制命令并选择必要检查。结构校验只证明头信息可解析；独立场景验证不证明客户端自动发现已生效。改动 skill、发现入口或读取路径时，用 [agent-experience](../agent-experience/SKILL.md) 检查上下文成本。

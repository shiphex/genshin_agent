# 文字规范

保留必要含义，再删除重复与修饰。它负责文字判断；文档归位、模板及检查编排由 [doc](../doc/SKILL.md) 负责，长期规则见[文档规范](../../../docs/AGENTS.md)。

## 步骤

1. 从用户请求确定具体范围和只读／修改模式，不推定为全仓审查。读原段落及其事实维护位置，必要时定向查看代码或记录。
2. 列出承载含义的成分：主体与动作、条件与时序、必须／允许／禁止、否定与例外、责任与副作用、失败结果、不确定性及兼容承诺。
3. 对每处选择保留、补充、精简、重组或暂缓。缩短后逐项核对上述成分，不能为了字数上限删掉验证条件或失败保护。删除实现推演和无用修饰，保留非显然且能防止误用的原因。
4. 用直接动作和稳定[术语](../../../docs/terminology.md)表达。必要英文保持原样；不要用抽象“边界”“契约”替代具体字段、条件和责任。代码已清楚表达的流程不再逐行解释。
5. 保留使用处必需的行为、失败和责任说明；详细原理、历史、接口及命令链接权威位置。消除重复不能让读者丢失必要前提。
6. 对照原文逐项复核修改含义，再检查差异与适用预算。发现会改变重要行为或用户约束的改法，先报告证据与影响，不作为文字整理直接实施。

## 验证与边界

例如“仅在新目录验证通过后才切换当前指针；失败保留原指针”不能缩成“完成后切换指针”。可写“新目录验证通过后切换指针，失败保留原指针”。

只读审查不编辑。冻结文档只按授权报告问题，不现代化原文；不以删字数量衡量改进。用户可观察提示词或诊断文案若改变行为，需相应行为验证，不只检查 Markdown。

# 测试隔离与稳定性

测试正确性要适用于实际执行拓扑。先读[开发流程](../../../docs/development.md#验证)、受影响测试与当前[CI 配置](../../../.github/workflows/ci.yml)，命令选择交给 [pre-push-checks](../pre-push-checks/SKILL.md)。本地通过与远端 CI 通过分别报告。

## 设计和修改测试

1. 确认同用例、同进程、不同测试进程或不同作业是否会共享路径、端口、环境变量、时钟或缓存；进程隔离不代表主机资源隔离。每项资源应有拥有者、原子分配、就绪信号和清理完成条件。
2. 测试使用独立 TemporaryDirectory；服务绑定回环地址和端口0，取得系统分配地址，不先扫描“空闲端口”。必须不存在的路径用排他创建。稳定的预期ID／路径文本与真实可写目录、运行端口分开，不改无资源占用的解析样例。
3. 等待可观测的就绪／完成事件，用期限限制等待；不以固定 sleep 证明启动完成。验证竞争时用屏障或事件控制交叠；涉及时间行为时使用注入时钟，并恢复原时钟。
4. 获得资源后立即注册清理，失败也关闭文件、服务器、线程和子进程，并等待实际结束。恢复环境变量、cwd、mock等进程全局状态时保留“原本不存在”与“原本存在”的区别；缩小修改范围。
5. 核对 Windows／POSIX 的句柄释放、路径、环境变量大小写、时间精度和信号差异。依赖平台语义的断言使用实际读回值；不可运行的平台明确未验证，另一平台通过不能代替。

## 调查偶发失败

保存失败命令、用例、提交／工作区、系统和运行时、CI作业／日志入口及稳定错误特征。优先比较同源码、同配置的失败与通过；区分基础设施故障、资源碰撞、未完成清理、全局状态污染及产品竞争，不能因重跑绿就归因机器。

先复现最小用例，再逐层增加到相关模块、独立进程并发或真实作业拓扑；每次只改变一个疑因。缺平台或日志时说明证据上限。修复前用负例／旧实现观察目标失败，修复后在同拓扑验证；共享资源问题需要独立进程交叠证据，生命周期问题需要清理完成证据。重跑次数只能补充，不能替代可重复的回归用例。

增加重试、延长超时、串行化所有测试或削弱断言不能代替根因修复。只有已测得的外部暂态或明确的等待预算才考虑相应重试／期限；说明依据。只读诊断不扩展为修改CI或重新触发远端作业的授权。

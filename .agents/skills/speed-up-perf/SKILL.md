# 性能实验与优化

先定义要改善的实际操作，再用相同条件测量。遵循[开发流程](../../../docs/development.md)，RAG 输入和运行产物由[模块说明](../../../rag/README.md)及[数据规则](../../../rag/docs/data.md)维护，本 skill 不维护第二套命令或阈值。

## 步骤

1. 明确操作的完成条件、典型与尾部工作量、允许的行为差异和停止条件。记录固定输入／语料哈希、代码身份、Top-K 等实际参数、运行环境及计时起止；区分读盘、建索引、冷启动、预热和复用索引查询，不将局部计时当成端到端耗时。
2. 先保存当前实现的测量，再改变一个可解释的因素。调用生产实现；不复制算法做 benchmark，不因怀疑某段循环就宣称它是瓶颈。先用阶段计时、调用次数或 profile 验证成本来源。
3. 对照双方使用相同输入、验证步骤、完成条件和缓存状态。性能比较采用多轮成对采样，交替先后顺序，保存全部逐次数据及轮次；报告采用的聚合、绝对值、比值和波动。110题均值与另一版本单题值不能组成同条件提升证据；一次离线评测也不是性能回归实验。
4. 改动后同时核对检索排序／分数等应保持的行为，以及用户实际操作的耗时。检索质量指标、语义覆盖与答案正确性分别报告；快了不能替代正确性。涉及内存时说明保留对象与峰值的测量范围。
5. 用优化前且确含目标成本的实现，或可控恢复该成本的负例，检验回退检查确实能失败。先测噪声，再讨论门槛；阈值须有目标环境中的重复测量依据，不能挑幸运样本、放宽门槛掩盖回退或照搬上游机器参数。当前检索 V0 只记录耗时，不自动设性能 CI 门禁。
6. 交付实际命令、源码和输入身份、原始记录位置、前后结果、行为验证及未覆盖范围。独立输出按既有分配器生成；不自动升级基线。没有实测收益时保留简短结论，停止扩展优化范围。

涉及时钟、并发或资源清理时按需读取 [ci-test-reliability](../ci-test-reliability/SKILL.md)；提交或交付前由 [pre-push-checks](../pre-push-checks/SKILL.md) 选择必要检查，避免重复运行仍有效的证据。

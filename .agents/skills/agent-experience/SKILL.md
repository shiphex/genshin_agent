# Agent 使用体验

让 agent（智能体）能发现所需信息，并以足够小的上下文完成工作。它审查发现与加载方式，不负责文档分类或产品行为；文档编辑使用 [doc](../doc/SKILL.md)。

## 步骤

1. 明确要完成的任务、首次可见信息与可用动作。先给目的、入口和关键约束，再按任务加载细节，不要求读完历史和全部实验结果。
2. 对每个延后加载的资源给出具体描述、可读取路径和触发时机；检查路径确实存在。将不可逆影响、授权和必要验证放在相关动作之前。
3. 每类事实只说明一次。工具参数规则放在对应参数说明，skill 引用项目规范；不要在系统指令、skill 和参考页复制同一段接口或命令。
4. 返回有界摘要、标识或路径以便回查；明确省略和截断。仅补充行动所需的相邻信息，不倾倒完整日志。
5. 用一个典型任务和一个小改动任务独立试读，记录读取文件、重复查找、遗漏约束及结果。若无模型 tokenizer，只报告字符／预算单位或读取范围，不冒充实际 token 节省。
6. 修改后比较总工作量：减少首次输入却增加反复搜索或误用不算改善。把文档归位问题交给 doc，文字含义问题交给 [prose-standard](../prose-standard/SKILL.md)。

## 验证与边界

局部 README 链接修复应能按根入口定位目标，无需读取完整历史、建立 Agent Note 或调用模型实验。显式读取 skill 的测试不代表客户端会自动发现它；客户端发现需要新会话或真实客户端验证。只读评审不执行工具写入。
